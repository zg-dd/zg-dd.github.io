一、前置安装

1.1 环境依赖概览

工具说明官方下载地址
NVIDIA 驱动显卡硬件驱动，是一切的基础NVIDIA 驱动官方下载
CUDA ToolkitGPU 编程的开发工具包（建议 12.4）CUDA 官方下载
cuDNNGPU 加速库cuDNN 官方下载
Conda包管理和环境管理工具（推荐 miniforge）miniforge 下载

1.2 安装步骤

第一步：安装 NVIDIA 驱动

必须是 NVIDIA 显卡，驱动是一切的基础。安装完成后验证：

nvidia-smi

输出显卡信息即表示安装成功。

第二步：查询支持的 CUDA 版本

打开 NVIDIA 控制面板，查看当前显卡支持的最高 CUDA 版本：

第三步：安装 CUDA Toolkit

前往官网下载对应版本，选择支持范围内的最新版本即可（我这里支持到 13.2.0）。安装方式选择精简安装。验证：

nvcc -V

第四步：安装 cuDNN

安装最新版本即可，按默认选项安装。

第五步：安装 Conda

推荐使用 miniforge，安装完成后 mamba 命令也会一并可用（速度比 conda 更快）。

二、创建虚拟环境

这里使用 mamba 创建虚拟环境，速度比 conda 更快。如果安装 miniforge 后 mamba 不存在，手动安装：

conda install -c conda-forge mamba

创建 Python 3.12 虚拟环境：

# -p 指定虚拟环境的完整路径（与 -n 二选一）
# Python 版本建议 3.10 以上，版本过低可能导致拉取操作失败
mamba create -p "F:\llama_factory\env" python=3.12 -y

激活虚拟环境：

mamba activate "F:\llama_factory\env"

三、安装 PyTorch

安装 PyTorch 前，需确保版本与本机 CUDA 兼容。在 PyTorch 历史版本对照表 查询对应命令，在虚拟环境中执行：

# 示例，具体版本号以官网查询结果为准
pip install torch==2.10.0 torchvision==0.25.0 torchaudio==2.10.0 --index-url https://download.pytorch.org/whl/cu130

安装完成后验证 CUDA 是否正常识别：

python -c "import torch; print(f'PyTorch版本: {torch.__version__}'); print(f'CUDA版本: {torch.version.cuda}'); print(f'CUDA可用: {torch.cuda.is_available()}'); print(f'GPU设备: {torch.cuda.get_device_name(0)}')"

本机运行结果：

PyTorch版本: 2.10.0+cu130
CUDA版本: 13.0
CUDA可用: True
GPU设备: NVIDIA GeForce RTX 3060 Laptop GPU

四、安装 LLaMA-Factory

4.1 克隆仓库

git clone --depth 1 https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory

也可以去 GitHub 页面 手动下载。

4.2 安装依赖

使用清华镜像源加速下载：

pip install -e ".[torch,metrics]" -i https://pypi.tuna.tsinghua.edu.cn/simple

注意：如果安装失败，检查 Python 版本。我最初使用 3.10 失败，换为 3.12 后成功。

4.3 验证安装

llamafactory-cli version

能正确输出版本号即表示安装成功。

4.4 启动 Web UI

在项目目录下执行：

llamafactory-cli webui

启动后访问 http://localhost:7860/ 进入可视化操作界面。

五、训练模型

以 Qwen2.5-0.5B-Instruct 模型为例进行微调训练。

  1. 将数据集文件放入项目 data 目录，例如 F:\LlamaFactory-main\data\train-fc-1000.json，文件内容参考：train-fc-1000.json

  2. 在 F:\LlamaFactory-main\data\dataset_info.json 中注册数据集，按照文件中已有的格式添加：

{
  "train-fc-1000": {
    "file_name": "train-fc-1000.json"
  }
}

5.2 配置训练参数

在 Web UI 中选择模型和数据集，配置训练参数：

内存不足问题处理：

笔记本 16G 内存，训练时默认启用 16 个进程并发，导致内存溢出。在额外参数中添加 preprocessing_num_workers 限制预处理进程数：

{"optim": "adamw_torch", "preprocessing_num_workers": 8}

训练完成后，在 Web UI 中加载模型验证效果：

5.4 导出模型

在 Chat 同级菜单的 Export 页面，调整导出目录后点击导出，保存模型文件。

5.5 通过 Ollama 加载模型

六、LLaMaFactory 模型参数详解

6.1 基本选择

6.1.1 模型分类

分类类型子类型说明适用场景
基础类型base通用基础模型，百科全书式知识通用任务
chat对话类模型聊天、交互式对话
instruct指令类模型根据指令执行任务
Math&Coder数学或代码专用模型数学计算、代码生成
多模态VL视觉语言模型图文混合处理
video视频理解模型视频内容分析
audio语音模型音频处理、语音识别

6.1.2 微调方法对比

方法原理优点缺点
Full（全参数）重新训练所有参数• 适应能力最强• 调优后性能最优• 资源消耗大• 可能丢失原有知识• 容易过拟合
Freeze（冻结）冻结部分参数，只训练部分层• 训练速度快• 过拟合风险小• 资源占用较少• 性能不如全参• 冻结点难以确定
LoRA在关键节点插入可训练的小模块• 资源占用少• 避免灾难性遗忘• 目前最热门• 复杂任务性能低于全参

💡 推荐：大多数场景下推荐使用 LoRA 微调方法。

6.1.3 其他参数

模型量化

概念：通过压缩浮点数位数来减小模型体积（如 32位浮点 → 8位整数）

量化类型说明
8位量化精度损失较小，资源节省明显
4位量化资源占用最小，精度损失较大

量化公式：

scale = 量化位数 / (max - min)
量化后值 = round(scale × 量化前值)

⚠️ 注意：还原后会损失精度。如果资源充足，建议不启用量化。

加速方式
  • 默认选项：auto（推荐）
  • 资源受限方案：unsloth + 4位量化

6.2 微调参数详解

6.2.1 学习率（Learning Rate）

📖 类比：学习时每次对知识的调整幅度

项目说明
取值范围通常在 0-1 之间
影响• 太大：调整幅度大，学习快，但容易受单次训练影响而走偏• 太小：过于谨慎，进步慢，但稳定不易改变已学知识
显存影响❌ 无影响

推荐配置：

场景学习率
LoRA 一般微调5e-5
保守微调4e-5
小数据集微调4e-5 ~ 5e-5
全参数微调1e-5（更谨慎）

🔧 辅助工具：使用学习率调节器（Scheduler）动态自我调整，兼顾速度和精度。

6.2.2 训练轮数（Epochs）

📖 类比：完整阅读一本书的遍数

项目说明
定义完整遍历数据集的次数
影响• 太大：过度学习，出现过拟合，“学傻了”• 太小：学习不充分，出现欠拟合
显存影响❌ 无影响，仅影响训练时间

推荐配置：

指标建议值
常规设置3 轮
取值范围3-6 轮，不超过 10 轮
Loss 监控控制在 0.5-1.5 之间
调整策略若 Loss 未增大，可适当增加轮数
数据集大小数据集越小，轮数应越少

6.2.3 批量大小（Batch Size）

📖 类比：一口气学完多少章节再总结

项目说明
定义每次更新参数所使用的样本数量
影响• 大批量：学得快，掌握全局，但泛化能力差，易过拟合• 小批量：学得精细，细节到位，泛化能力强，但速度慢
显存影响✅ 影响很大，单批量越大，显存消耗越大

核心参数：

参数符号说明
批处理大小A每个 GPU 一次处理的样本量
梯度累积B累计多少次才更新参数

理解案例：

设 A=2, B=5
→ 每个 GPU 一次学 2 条
→ 等学完 5 次（攒了 10 条）后算一个批次完成，调整参数

💡 设计目的：梯度累积用于解决 GPU 单次处理显存有限但又需要大批次训练的场景。

推荐配置：

场景批处理大小(A)梯度累积(B)
小数据集微调1-26-10，逐步调大以加快速度

🔗 配合原则：大学习率配大批量，小学习率配小批量。

6.2.4 截断长度（Cutoff Length）

📖 类比：一次能记住的某一章相关知识的量

项目说明
定义模型处理文本时一次能接受的最大 token 数量
理想值数据集中 token 最多的那条样本的长度
影响• 过小：学到不完整知识，影响学习效果• 过大：浪费显存，需压低批次防止溢出
显存影响✅ 影响较大：显存 ∝ (cutoff_len)² × batch_size

显存估算案例：

截断长度 1024，单批次 8
→ 改为 2048 时，单批次可能需要降到 4
→ 否则显存可能溢出导致训练终止

推荐策略：

数据分布建议
样本长度均衡设置为最大样本的 token 长度
极少数超长样本方案1（推荐）：剔除异常样本方案2：选择 99% 分位线的长度

辅助工具：

  • Tiktokenizer - 在线 Token 计算器
  • LLaMAFactory 自带 length_cdf.py 脚本
  • 直接将最长样本丢给 AI 助手估算 Token 数

6.2.5 LoRA 秩（LoRA Rank）

📖 类比：学习时采用的解题方法种类

技术原理：

LoRA 微调不动原始模型参数，用两个小矩阵相乘得到增量矩阵 ΔW：

假设 512×1024 的大矩阵
可用 512×8 和 8×1024 两个小矩阵乘积得到
→ LoRA 的秩就是 8

缩放系数 α：

最终权重 W = W₁ + α × ΔW
一般设置 α = 2 × rank
项目说明
定义使用 LoRA 微调时参数关联性的程度
影响• 秩小：方法稳定，不易过拟合，显存占用小，但可能无法处理复杂问题• 秩大：思路更多，能解决复杂问题，但容易强行关联不相关内容，造成过拟合
显存影响✅ 有影响，但不是太大

推荐配置：

参数建议值
初始秩8
尝试范围8-16 逐渐尝试
缩放系数2 × rank
调整策略若学习效果不足，逐渐调大

6.2.6 验证集比例（Validation Split）

📖 类比：留多少题目用于考试测验学习效果

项目说明
定义数据集中用于验证的比例（0-1 之间）
影响• 不设置也可• 设置后可在 Loss 曲线中观测验证集表现
显存影响❌ 无影响，仅划分数据比例

推荐配置：

数据集规模验证比例说明
小数据集（<1000）0.1-0.2（10%-20%）保证验证集总数 ≥100
大数据集（>10000）0.05-0.1（5%-10%）-
复杂任务适当调大用于监控防止过拟合
简单任务适当调小避免浪费训练数据

⚠️ 重要：验证集总数尽量不要小于 100，否则验证结果不足以反映学习情况。

6.3 开始训练

6.3.1 显存估算（仅供参考）

显存组成：

组成部分估算值说明
基础模型0.5B ≈ 1GB经验数据
LLaMAFactory≈ 1GB框架占用
LoRA 适配器≈ 0.5GB适配器占用
训练过程数据与 (token截断长度 × 单批量大小) 相关见下方公式

训练数据显存公式：

1024 截断长度，批次为 1 的情况下 ≈ 2.5GB
单次处理 token 每加 1k → 显存增加 2.5GB
批量每 +1 → 显存增加 2.5GB
与梯度累计无关（梯度累积本身就是为降低大批量显存占用设计的）

实战案例：

硬件：RTX 4060（8GB 显存）
模型：Qwen2.5-0.5B-Instruct
配置：截断长度 1024，单批量 2，梯度累积 8，LoRA 微调

显存计算 = 1 + 1 + 0.5 + 2.5 × 2 = 7.5 GB ✅ 够用

6.3.2 Loss 曲线分析与调优

Loss 表现可能原因解决方案
平稳小波动但不下降• 模型没学到东西• 数据集无规律或存在大量异常数据调大学习率
下降太慢，未触底• 数据集没学完• 学习不够彻底调大训练轮数
上下大幅震荡• 学习率过大，参数调整过度• 批量太小，受单批次噪声影响大适当调低学习率或调大批量
开始快降，最后平缓不触底• 学习率达到瓶颈• 达到局部最优解适当调大学习率，配合调大批量
下降后回升• 数据集有问题• 学习率异常大，破坏最优解修正数据集，去除异常数据

Loss 目标区间：0.5 - 1.5

6.4 参数调优流程建议

  
graph TD
    A[开始训练] --> B{观察 Loss 曲线}
    B -->|平稳不下降| C[调大学习率]

    D --> H
    E --> H
    F --> H
    G --> H
    H --> I{Loss 是否在 0.5-1.5?}
    I -->|是| J[✅ 训练成功]
    I -->|否| B

参数推荐值显存影响关键提示

七、问题排查

7.1 ollama 模型加载报错 500

现象：ollama 加载模型成功，但聊天时报错 500；跑官方 qwen2.5-0.5B-Instruct 模型正常。

原因：LLaMA-Factory 内置的 llama.cpp 版本过低，导致转换的 GGUF 文件与 ollama 不兼容。

解决方案：单独使用最新版 llama.cpp 重新转换模型。

7.1.1 克隆 llama.cpp

git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp
pip install -r requirements/requirements-convert_hf_to_gguf.txt

7.1.2 转换模型

# 将训练好的模型转换为 GGUF 格式
python convert_hf_to_gguf.py "I:\ai-model\train_2026-04-11-12-40-19" --outtype f16 --outfile "I:\ai-model\my-qwen\qwen-finetuned.gguf"

7.1.3 创建 Modelfile

在 I:\ai-model\my-qwen\ 目录下创建 Modelfile：

FROM I:\ai-model\my-qwen\qwen-finetuned.gguf

TEMPLATE """{{ if .System }}<|im_start|>system
{{ .System }}<|im_end|>
{{ end }}{{ range .Messages }}{{ if eq .Role "user" }}<|im_start|>user
{{ .Content }}<|im_end|>
<|im_start|>assistant
{{ else if eq .Role "assistant" }}{{ .Content }}<|im_end|>
{{ end }}{{ end }}"""

SYSTEM """You are Qwen, created by Alibaba Cloud. You are a helpful assistant."""

PARAMETER stop "<|im_end|>"
PARAMETER num_ctx 4096

说明：内容与导出时的 Modelfile 一致，只需在开头添加 FROM 指向新的 GGUF 文件路径。

7.1.4 重新加载模型

# 移除旧模型
ollama rm mymodel-Qwen2.5-0.5B-Instruct

# 创建新模型
ollama create mymodel-Qwen2.5-0.5B-Instruct -f I:\ai-model\my-qwen\Modelfile

# 测试运行
ollama run mymodel-Qwen2.5-0.5B-Instruct "hello"
